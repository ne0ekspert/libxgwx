# Native SFC acceptance fixtures

These synthetic projects were constructed in offline XG5000 4.82.1 on an
XGI-CPUE on 2026-10-08. They contain no user production program.

- `native-loop.xgwx`: `Start` label → initial step `S0` → `%MX0` transition →
  step `S1` with comment `Ready for cycle` → `%MX1` transition → `Start` jump.
- `edited-native-roundtrip.xgwx`: library/UI changes `%MX0` to `%MX2` and the
  step comment to `Cycle active & ready`, reopened and saved by XG5000.
- `native-action.xgwx`: the edited chart with an `N (Non stored)` variable
  action `%MX10` attached to `S0`.
- `new-xgi-sfc.xgwx`: fresh blank XGI-CPUE SFC project `NewProject`, PLC `LSPLC`,
  and empty main block `NewProgram`. This is the extension's New File template.
- `new-xgi-sfc-roundtrip.xgwx`: that blank template reopened, checked, and saved
  under a new filename in XG5000; the SFC tree and local symbol payloads are preserved.

Strict all-program Check Program had logic, syntax, duplicate-coil and strict
type checks enabled: all three charts reported **0 errors, 0 warnings**.
The blank template reopens normally; strict all-program checking reports
`E0000` (empty program) and `E4001` (no initial step), with no warnings. These
are expected until the user adds chart structure in XG5000.
The generated edit and XG5000 Save As result have identical SFC entity trees
and local variable tables. The UI harness produced exactly the same project
bytes as `cargo run --features write --example sfc_acceptance`.

SFC uses `SFC_ProgramList` XML, not binary ladder `ProgramData`. Transition
properties are mirrored in the adjacent type-9 annotation entity; both copies
must be updated together. The parser retains unknown entity kinds/attributes.

Structural acceptance on 2026-10-08 used `sfc_structure_acceptance`:

- `structural-build.xgwx`: generated from the blank template; label `Cycle`,
  initial step `Idle` with N action `%MX10`, transitions `%MX2/3/4`, ordinary
  steps `Run` (comment `Cycle & ready`) and `Done` (N action `%MX11`), then a jump.
- `structural-delete.xgwx`: removes `Run` and its following `%MX3` transition.
- `structural-rename.xgwx`: edits the native action chart: `S0` becomes `Boot`,
  action `%MX10` becomes `%MX12`, transition `%MX2` becomes `%MX5`, and `S1`
  becomes the initial step.
- Each corresponding `*-native-roundtrip.xgwx` is its native Save As result.

All three structural cases passed strict all-program Check Program with
**0 errors, 0 warnings**. Save As preserves typed rows (including initial
status and action operands) and local symbol payloads. Compiled internal names
are regenerated by XG5000. The rendered webview/WASM harness generated exactly
the build and deletion acceptance bytes while exercising add, move, delete,
name/comment/condition edits, initial status, N actions, and label/jump updates.
This harness mocks the VS Code document host; the native checks use real XG5000.

Supported structural writes are dense two-column linear main blocks with
steps, direct `%MX` BOOL transitions, labels/jumps, and one direct BOOL action per step.
Unknown properties, branches, bookmarks/breakpoints, unsupported program languages,
nested charts, and unknown qualifiers remain guarded. Existing bounded comment
and condition edits remain available independently of structural support.

SFC local symbols retain their native records. A separate SFC decoder recognizes
the reserved TRANS/GOTO_INIT classes alongside ordinary IEC declarations.


`action-qualifiers.xgwx` contains all nine variable action qualifiers: N=1,
R=2, S=4, L=8, D=16, P=32, SD=64, DS=128, SL=256. Each is attached to
its own step; the five timed qualifiers use `T#2s`. Native XG5000 4.82.1
strict all-program Check Program reports **0 errors, 0 warnings**.
`action-qualifiers-native-roundtrip.xgwx` is its Save As result: all operands,
qualifiers, times, typed rows, and local symbol payloads are retained.
The native qualifier picker and an independently created L action confirm
that qualifier codes are bit flags. Variable-action auxiliary fields remain
empty and TimeIndex is zero; other layouts are guarded.

ST and typed-variable acceptance on 2026-10-08:

- `native-st-programs.xgwx`: native ST action `UpdateValues`, ST transition
  `Ready`, DINT `Count`, and TON `Delay`. Action code increments Count and calls
  Delay; the transition assigns `TRANS := Count >= 10 AND Delay.Q`.
- `st-programs-generated.xgwx`: `sfc_st_acceptance` adds all 19 primitive IEC
  types and instances of TON, TOF, TP, CTU_DINT, CTD_DINT, CTUD_DINT, R_TRIG,
  F_TRIG, RS, and SR. The ST action calls every instance, uses ADD, writes WORD,
  DWORD and LWORD values, and the ST transition reads Count and Delay.Q. Named
  BOOL `Value_BOOL` is also used as a variable action and transition.
- `st-programs-native-roundtrip.xgwx`: native Save As of that generated file.

Both native ST and generated ST projects passed offline XG5000 4.82.1 strict
all-program Check Program with **0 errors, 0 warnings**. Save As preserves the
complete row/source model and all declared types, instance types, descriptions,
and reserved variables. Native compilation names and allocations are regenerated.

ST action blocks use LanguageType=1; transition blocks use LanguageType=2;
both use Language=4. The entity's PropertyProgram is 1. CodeList is a compressed
UTF-16LE payload with CodeCount measured in UTF-16 units. Standard instances have
primitive selector code 24 with their native FB type reference. SFC system locals
use classes 11 and 12 with flag 4. Their raw records are preserved during insertion
and deletion. The ST writer guards bookmarks, breakpoints, post-scan actions,
unknown metadata and unsupported nested-program languages. Counter names are
native typed variants, and latch ST parameter names are R_1 and S_1.
